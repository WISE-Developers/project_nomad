# Nomad Coverage Overlay — Step 6 (Drift × Test Net → Danger Zones)

**Read-only.** Test runner: **Vitest** (frontend + backend). Method: static mapping of test file ↔ source file, reading test bodies to judge whether the *specific behavior a refactor would touch* is pinned. No suite was run; no source modified; no processes spawned.

Inputs: `nomad-dip-violations.md` (Step 3), `nomad-soc-findings.md` (Step 4), `nomad-ocp-lsp-isp-findings.md` (Step 5).

Classification key:
- **COVERED** — the at-risk behavior is pinned by an assertion; a behavior-preserving refactor would break a test if it regressed.
- **THIN** — some tests touch the unit, but NOT the exact behavior a refactor would alter (or only the happy path / a delegate).
- **UNCOVERED** — no test exercises the unit at all → danger zone.

## Danger Zones — Ranked by Remediation Risk (riskiest first)

Risk = (architectural drift severity) × (absence of test net) × (blast radius of the refactor).

1. **ModelExecutionService.ts — `engineType` switches (L122, L273)** — OCP FAIL, **UNCOVERED**, and the keystone of the backend Data-Service "READY-WITH-PREP" blocker. Deleting two switches for a resolver with zero characterization is the single riskiest move. *Write #5 first.*
2. **api/routes/v1/results.ts — concrete `getFireSTARREngine` wiring** — OCP FAIL, **UNCOVERED** at the route boundary (only mocked away in an MCP test). Four call sites must be redirected to a resolver; an HTTP-level net is needed. *Write #6.*
3. **ExportBundleBuilder.ts — builder + store + import-time `setInterval`** — SoC smell, **UNCOVERED**; the import-side-effect timer is the sharpest edge and is exactly what testing/extraction must isolate. *Write #4 (builder + BundleStore).*
4. **ModelResultsService.ts — app→infra concrete reach** — DIP MED, **UNCOVERED**; pin outputs before inverting the repository dependency. *Write #3.*
5. **DefaultOpenNomadAPI / IOpenNomadAPI — partial "not implemented" roster** — LSP FAIL, **THIN**; only 3 of ~12 throwing methods pinned. Mid risk because OCP is clean (new adapters coexist) but the contract split needs the full roster pinned first. *Extend #8.*
6. **TimeRange.ts — `fromISO`/`validateDates`** — DIP HIGH but lowest *remediation* risk: the parsing delegate is already COVERED, so only TimeRange's own wrapper/validation needs a quick spec before re-pointing the dependency. *Write #1.*

**Not danger zones:** `dateParsing.ts` (COVERED), `IFireModelingEngine`/`FireSTARREngine` impl behavior (COVERED via buildCommand/output-config tests), repository ports (PASS on all three seams in Step 5, supported by `KnexNotificationPreferencesRepository.test.ts`).
